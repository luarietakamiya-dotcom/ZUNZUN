姫「独自AIを別ルートで完璧に仕上げて。わからない部分があれば自分で調べ、検証も行い、私の助けがなくても最強にして」を受けて着手。従来のA-003製品化中止は本体に維持し、新しい独立ルートを開発する。OpusのLyricSync連携と同じファイルを編集しない。

- 対象: `experiments/independent-sync/` と本記録。共同作業の開始/終了だけ `docs/AI_COLLABORATION.md` に記録。

- 公開の独立正解ラベルを調達して評価する。姫に追加のタップ作業は依頼しない。
- ASR生成文を正解歌詞にしない。既知本文をCTC音響証拠へ照合し、無音・辞書外・不成立・不一致を保留できることを必要条件にする。
- 「完璧」「最強」は測定前の達成実績として扱わない。ベンチマーク条件、閾値、除外、失敗を残す。

## 設計の初期仮説
従来のWhisper微小モデルや非商用MMSに代え、日本語CTCのApache-2.0候補を確認する。長い曲は重複区間で推論し、切れ目の文脈を持たせて結合。音素/文字の単調経路と不一致検査を分け、確率の数値を校正済み信頼度と呼ばない。モデルの出力間隔と受容野を実測し、固定400ms先行表示は歌唱時刻の精度から分離する。

## 実装したもの

`experiments/independent-sync/` に分離した Python CLI。重複区間つき音響推論、正確な CTC Viterbi、発音候補 DAG の最尤経路探索、繰り返す本文の出現順での行対応、ハッシュでの入力一致確認、未一致を分母に残す評価、固定資産の取得/検証、異常検査を実装した。新規学習済みの独自基盤モデルではなく、公開の音響モデルと独自の照合・検査を組み合わせた研究ルート。

全結果は `review` または `unmatched`。本文に存在しない文字を blank として捨てない。ゼロ幅時刻を正しい時刻へ埋め直さない。無音・非有限値・不可能経路・メモリ上限・入力不一致を拒否する。モデル間の候補範囲は出せるが、一致を正しさの証明にはしない。本体への自動適用は実装しない。

## 実データと評価の限界

- Qwen 全文一括は393単位中285単位がゼロ幅、初期の厳密対応では不成立。区間版でも RAB 1参照点が未一致で、19点だけを分母にせず20点で採点した。公式の強制照合は音声向けで、歌声精度を保証する根拠にはしない。

## 整合性と異常系の検証

単体テスト18件通過: 小規模の全経路列挙との CTC/DAG 最適値比較、同音の連続に blank が必要な条件、読み候補が行境界を越えないこと、不可能経路、非有限値、辞書外、メモリ制限、繰り返す本文の出現順、潰れた時刻の局所保留、入力ハッシュ/本文不一致、重複ID、未一致を含む分母、候補合成の入力/モデル重複検査、ZIP のパス逸脱。

さらに本物の base 音響モデルで RAB の5行・17.81秒区間を実行した。

- 全無音1秒は推論前に拒否。
- 音量を0.1倍にしても5行の開始時刻差は全て0ms。
- 先頭へ1.28秒の無音を足す試験は、期待する1.28秒移動を引いた後、4行が0〜20ms差だが1行が **+3.6秒**。中央値だけならほぼ0に見えるため、最大値/各差も保存した。自動適用を止める具体的な失敗。

この整合性試験は絶対精度の検証ではない。Python 実装の18件が通っても音楽の精度は保証されない。ブラウザ、スマホ、WebGPU、WASM、MP4の書き出し、本物のLyricSyncとの通信はこのルートでは検証していない。本体未変更のため既存JSの全テストを再実行したという主張もしない。

## 判断

**独立エンジンと再現/比較環境は実装済み。完全自動・完璧な歌詞同期には未達。** 精度を満たしていないものを本体へ追加しない。単一曲で良いモデルや補正を採用せず、独立した精密歌唱ラベルでの曲単位評価と、先頭無音での数秒移動の解消が必要。ユーザーに新たな採点作業をお願いする結論にはしない。独自重みの学習、十分な歌唱データ調達、全曲保証を完了した扱いにしない。
